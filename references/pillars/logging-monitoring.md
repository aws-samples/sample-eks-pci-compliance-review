# Pillar: Logging, Monitoring & Audit (LOG1-LOG10)

Focus: Comprehensive logging, monitoring, and audit trail implementation to satisfy PCI DSS requirements for recording, reviewing, and protecting audit data. Grade each check PASS / FAIL / N/A with evidence, severity, and PCI DSS requirement mapping.

PCI DSS anchor: Requirement 10 (log and monitor all access to system components and cardholder data), Requirement 10.2.1 (audit log of user access), Requirement 10.2.2 (audit log details), Requirement 10.3.1/10.3.2 (read-only log access), Requirement 10.3.3/10.3.4 (log retention/storage), Requirement 10.4 (review audit logs), Requirement 11.5.1 (intrusion detection).

Reference: [Building PCI DSS-Compliant Architectures on Amazon EKS — §7 Logging, Monitoring, and Audit Trails](https://aws.amazon.com/blogs/containers/building-pci-dss-compliant-architectures-on-amazon-eks/)

| Check ID | Check Name | CDE Scope | Data Source | What to Look For | Severity if Failed | PCI DSS Req | Recommendation |
|----------|------------|-----------|-------------|------------------|-------------------|-------------|----------------|
| LOG1 | EKS control plane logging enabled (all types) | Cluster | `aws eks describe-cluster --name {cluster}` (logging.clusterLogging) | All 5 log types enabled: `api`, `audit`, `authenticator`, `controllerManager`, `scheduler` | Critical | 10.2.1 | Enable all EKS control plane log types (api, audit, authenticator, controllerManager, scheduler). These logs record administrative actions and cluster-level activities essential for PCI DSS Req 10.2.1 audit requirements. See: https://docs.aws.amazon.com/eks/latest/userguide/control-plane-logs.html |
| LOG2 | CloudTrail recording EKS API activity | Cluster | `aws cloudtrail describe-trails` + `aws cloudtrail get-trail-status` | An active CloudTrail trail captures EKS management events (CreateCluster, UpdateCluster, DeleteNodegroup, etc.) | High | 10.2.1 | Ensure CloudTrail is active and recording EKS API management events. CloudTrail provides the AWS-level audit trail for compliance. Supports PCI DSS Req 10.2.1. See: https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-create-and-update-a-trail.html |
| LOG3 | Kubernetes audit logs captured | Cluster | `aws eks describe-cluster` (logging includes `audit`) + `aws logs describe-log-groups --log-group-name-prefix /aws/eks/{cluster}/cluster` | Kubernetes audit logs are flowing to CloudWatch Logs (log group exists and has recent log streams) | Critical | 10.2.2 | Enable Kubernetes audit logging via EKS control plane logs. Audit logs record cluster-level activities including who did what, when, and from where. Essential for PCI DSS Req 10.2.2 (event detail logging). See: https://docs.aws.amazon.com/eks/latest/userguide/control-plane-logs.html |
| LOG4 | Log collection agent deployed (Fluent Bit) | Cluster | `kubectl get daemonsets -A` (look for fluent-bit, fluentd, or aws-for-fluent-bit) | A log collection DaemonSet (Fluent Bit, Fluentd, or AWS for Fluent Bit) is running on all nodes to collect container logs | High | 10.2.1 | Deploy Fluent Bit as a DaemonSet to collect container logs cluster-wide and forward them to CloudWatch Logs or your centralized logging solution. Supports PCI DSS Req 10.2.1. See: https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Container-Insights-setup-logs-FluentBit.html |
| LOG5 | CloudWatch log retention >= 1 year | Cluster | `aws logs describe-log-groups --log-group-name-prefix /aws/eks/{cluster}` (retentionInDays) | EKS-related log groups have retention set to at least 365 days (PCI DSS requires minimum 12 months online) | High | 10.3.3, 10.3.4 | Set CloudWatch Logs retention to at least 365 days for all EKS-related log groups. PCI DSS Req 10.3.3 requires audit log history for at least 12 months, with the most recent 3 months immediately available. See: https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Working-with-log-groups-and-streams.html |
| LOG6 | Container Insights enabled | Cluster | `aws cloudwatch list-metrics --namespace ContainerInsights --dimensions Name=ClusterName,Value={cluster}` | CloudWatch Container Insights metrics exist for the cluster (namespace `ContainerInsights` with cluster dimension) | Medium | 10.2.2 | Enable CloudWatch Container Insights for enhanced container-level observability (CPU, memory, network, filesystem metrics per pod and node). Supports PCI DSS Req 10.2.2 for event detail collection. See: https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/deploy-container-insights-EKS.html |
| LOG7 | GuardDuty EKS protection enabled | Cluster | `aws guardduty list-detectors` + `aws guardduty get-detector` (features: EKS_AUDIT_LOGS, EKS_RUNTIME_MONITORING) | GuardDuty is enabled with EKS Audit Log Monitoring and/or EKS Runtime Monitoring features active | High | 11.5.1 | Enable GuardDuty with EKS Audit Log Monitoring and Runtime Monitoring. GuardDuty provides managed threat detection analyzing Kubernetes audit logs and runtime container activities. Supports PCI DSS Req 11.5.1 (intrusion detection). See: https://docs.aws.amazon.com/guardduty/latest/ug/guardduty-eks-audit-log-monitoring.html |
| LOG8 | Security Hub enabled | Cluster | `aws securityhub describe-hub` | AWS Security Hub is enabled in the account/region for centralized security posture management | Medium | 10.4 | Enable AWS Security Hub for centralized security findings from GuardDuty, Inspector, Config, and other services. Provides a unified view for PCI DSS Req 10.4 audit log review. See: https://docs.aws.amazon.com/securityhub/latest/userguide/securityhub-settingup.html |
| LOG9 | Log access restricted (append-only/read-only) | Cluster | `aws logs describe-resource-policies` + IAM policy review | EKS application roles do not have `logs:DeleteLogGroup`, `logs:DeleteLogStream`, or `logs:PutRetentionPolicy` permissions on their own log groups | Medium | 10.3.1, 10.3.2 | Restrict log access so that application workloads cannot delete or modify their own audit logs. Use IAM policies to enforce append-only logging. Supports PCI DSS Req 10.3.1 and 10.3.2 (read-only access to log data). See: https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/iam-identity-based-access-control-cwl.html |
| LOG10 | CloudWatch alarms for security events | Cluster | `aws cloudwatch describe-alarms` (filter for EKS-related alarms) | CloudWatch alarms exist for key security events: authentication failures, authorization denials, API 4xx/5xx rates, or custom metric filters on audit logs | Medium | 10.4 | Configure CloudWatch alarms for security-relevant events (repeated auth failures, privilege escalation attempts, unusual API patterns). Supports PCI DSS Req 10.4 (timely detection of security events). See: https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/AlarmThatSendsEmail.html |
