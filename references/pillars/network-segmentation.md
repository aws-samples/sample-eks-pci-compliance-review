# Pillar: Network Segmentation (NET1-NET9)

Focus: Network policies and controls that restrict traffic between pods, enforce encryption in transit, and implement CDE perimeter protection. Grade each check PASS / FAIL / N/A with evidence, severity, and PCI DSS requirement mapping.

PCI DSS anchor: Requirement 1.3.2 (restrict inbound/outbound traffic to CDE), Requirement 1.4.1 (NSCs between trusted and untrusted networks), Requirement 1.4.2 (inbound traffic restricted), Requirement 1.4.4 (outbound traffic restricted), Requirement 2.2 (secure hardening baseline).

Reference: [Building PCI DSS-Compliant Architectures on Amazon EKS — §4 Network Segmentation](https://aws.amazon.com/blogs/containers/building-pci-dss-compliant-architectures-on-amazon-eks/)

| Check ID | Check Name | CDE Scope | Data Source | What to Look For | Severity if Failed | PCI DSS Req | Recommendation |
|----------|------------|-----------|-------------|------------------|-------------------|-------------|----------------|
| NET1 | Default-deny network policy in CDE namespaces | CDE-only | `kubectl get networkpolicies -n {cde} -o json` | A NetworkPolicy exists that denies all ingress AND egress by default (empty podSelector `{}`, policyTypes includes both Ingress and Egress, no rules allowing traffic) | Critical | 1.3.2, 1.4.1 | Apply a default deny-all NetworkPolicy to each CDE namespace before selectively permitting required traffic. Example: `spec: { podSelector: {}, policyTypes: [Ingress, Egress] }`. This is the foundational network segmentation control for PCI DSS Req 1.3.2 and 1.4.1. See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| NET2 | Ingress network policies restrict source | CDE-only | `kubectl get networkpolicies -n {cde} -o json` | NetworkPolicies with ingress rules specify explicit source namespaces, pods, or CIDR blocks — not open to all | High | 1.4.2 | Define explicit ingress rules in NetworkPolicies that allow traffic only from known, authorized sources (specific namespaces, pod labels, or CIDR ranges). Supports PCI DSS Req 1.4.2 (inbound traffic to CDE restricted to necessary sources). See: https://kubernetes.io/docs/concepts/services-networking/network-policies/ |
| NET3 | Egress network policies restrict destination | CDE-only | `kubectl get networkpolicies -n {cde} -o json` | NetworkPolicies with egress rules specify explicit destination namespaces, pods, or CIDR blocks — not open to all | High | 1.4.4 | Define explicit egress rules in NetworkPolicies that allow traffic only to known, authorized destinations. Supports PCI DSS Req 1.4.4 (outbound traffic from CDE restricted to necessary destinations). See: https://kubernetes.io/docs/concepts/services-networking/network-policies/ |
| NET4 | TLS enforcement for service communication | CDE-only | `kubectl get services -n {cde}` + service mesh config (Istio/Linkerd mTLS) or Service Connect TLS | Service-to-service communication within CDE is encrypted via mTLS (service mesh), TLS termination, or Service Connect TLS configuration | High | 2.2 | Enforce TLS for all service-to-service communication within the CDE. Use a service mesh (Istio/Linkerd with mTLS), or configure TLS directly on services. Supports PCI DSS Req 2.2 (encryption in transit as part of secure hardening). See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| NET5 | Admin network policies (ClusterNetworkPolicy) | Cluster | `kubectl get clusternetworkpolicies` (VPC CNI v1.21.1+) | Admin-tier ClusterNetworkPolicies exist for organization-wide CDE isolation that cannot be overridden by namespace-level policies. Mark N/A if VPC CNI < v1.21.1 or K8s < 1.29 | Medium | 1.4.1 | Use Admin Network Policies (ClusterNetworkPolicy, requires VPC CNI v1.21.1+, K8s 1.29+) for centralized, cluster-wide CDE isolation rules that developers cannot override. Supports PCI DSS Req 1.4.1. See: https://docs.aws.amazon.com/eks/latest/userguide/cni-network-policy.html |
| NET6 | Pod security groups integration | CDE-only | `kubectl get pods -n {cde} -o json` (annotations `vpc.amazonaws.com/pod-sg`) | CDE pods use security groups for pods (SGP) to apply EC2-level network controls directly to pod ENIs | Medium | 1.3.2 | Configure security groups for pods on CDE workloads for fine-grained, AWS-native network control at the pod level. Supports PCI DSS Req 1.3.2. See: https://docs.aws.amazon.com/eks/latest/userguide/security-groups-for-pods.html |
| NET7 | VPC Flow Logs enabled | Cluster | `aws ec2 describe-flow-logs --filter "Name=resource-id,Values={vpc-id}"` | VPC Flow Logs are enabled for the VPC hosting the EKS cluster, capturing network traffic metadata | High | 10.2.1 | Enable VPC Flow Logs for comprehensive network traffic monitoring and security auditing of the CDE network perimeter. Supports PCI DSS Req 10.2.1 (audit log of network activity). See: https://docs.aws.amazon.com/vpc/latest/userguide/flow-logs.html |
| NET8 | Network Firewall for CDE perimeter | Cluster | `aws network-firewall list-firewalls` + `aws network-firewall describe-firewall` | AWS Network Firewall is deployed for CDE VPC/subnet perimeter protection. Mark N/A if CDE traffic does not traverse a network boundary requiring stateful inspection | Medium | 1.3.2 | Deploy AWS Network Firewall for stateful inspection and filtering of traffic at the CDE perimeter. Supports PCI DSS Req 1.3.2. Mark N/A if architecture does not require perimeter firewall (e.g., all traffic is east-west within VPC). See: https://docs.aws.amazon.com/network-firewall/latest/developerguide/what-is-aws-network-firewall.html |
| NET9 | AWS PrivateLink for AWS service access | Cluster | `aws ec2 describe-vpc-endpoints --filters "Name=vpc-id,Values={vpc-id}"` | VPC endpoints (PrivateLink) exist for AWS services accessed by CDE workloads (e.g., S3, ECR, STS, KMS, CloudWatch Logs) to avoid internet transit | Medium | 1.4.4 | Configure VPC endpoints (AWS PrivateLink) for AWS services used by CDE workloads. This ensures sensitive API traffic stays within the AWS network. Supports PCI DSS Req 1.4.4 (restrict outbound to necessary destinations). See: https://docs.aws.amazon.com/vpc/latest/privatelink/what-is-privatelink.html |
