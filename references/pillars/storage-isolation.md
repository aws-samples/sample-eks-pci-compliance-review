# Pillar: Storage Isolation (ST1-ST7)

Focus: Storage encryption, isolation, and access controls to protect cardholder data at rest and prevent unauthorized cross-tenant access. Grade each check PASS / FAIL / N/A with evidence, severity, and PCI DSS requirement mapping.

PCI DSS anchor: Requirement 3.5.1.2 (render PAN unreadable using strong cryptography with associated key management).

Reference: [Building PCI DSS-Compliant Architectures on Amazon EKS — §5 Storage Isolation](https://aws.amazon.com/blogs/containers/building-pci-dss-compliant-architectures-on-amazon-eks/)

> **Important note from the blog**: EBS volume encryption with KMS alone does NOT satisfy PCI DSS Requirement 3.5.1.2 for PAN protection. The AWS Encryption SDK should be used to encrypt PAN before writing to EBS volumes. This skill checks infrastructure-level encryption; application-level PAN encryption is out of scope.

| Check ID | Check Name | CDE Scope | Data Source | What to Look For | Severity if Failed | PCI DSS Req | Recommendation |
|----------|------------|-----------|-------------|------------------|-------------------|-------------|----------------|
| ST1 | EBS volumes encrypted with KMS | CDE-only | `aws ec2 describe-volumes --filters "Name=tag:kubernetes.io/cluster/{cluster},Values=owned"` | All EBS volumes attached to CDE nodes have `Encrypted: true` with a KMS key | High | 3.5.1.2 | Enable encryption at rest on all EBS volumes used by CDE workloads using AWS KMS. Note: EBS encryption alone does NOT satisfy Req 3.5.1.2 for PAN — use AWS Encryption SDK for PAN-level encryption. See: https://docs.aws.amazon.com/ebs/latest/userguide/ebs-encryption.html |
| ST2 | PVCs use encrypted StorageClass | CDE-only | `kubectl get pvc -n {cde} -o json` + `kubectl get storageclass -o json` | PersistentVolumeClaims in CDE namespaces reference a StorageClass with `encrypted: "true"` in parameters | High | 3.5.1.2 | Create a StorageClass with `parameters: { encrypted: "true", kmsKeyId: <key-arn> }` and ensure all CDE PVCs use it. Supports PCI DSS Req 3.5.1.2 for encryption at rest. See: https://docs.aws.amazon.com/eks/latest/userguide/ebs-csi.html |
| ST3 | No hostPath volumes in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (volumes[].hostPath) | No pods in CDE namespaces use hostPath volumes (also checked in PS8 — reinforced here for storage context) | Critical | 3.5.1.2 | Remove all hostPath volumes from CDE workloads. hostPath bypasses storage-level encryption and access controls, exposing the host filesystem. Use PVCs with encrypted StorageClasses instead. Supports PCI DSS Req 3.5.1.2. |
| ST4 | Per-tenant PVCs (no cross-namespace sharing) | CDE-only | `kubectl get pv -o json` (spec.claimRef) | PersistentVolumes bound to CDE PVCs are not shared across namespaces; each PV's `claimRef` points to a single CDE namespace | Medium | 3.5.1.2 | Ensure PersistentVolumes are bound to a single namespace's PVCs. Do not share storage volumes across namespace boundaries to maintain data isolation. Supports PCI DSS Req 3.5.1.2. |
| ST5 | Encryption in transit for CSI drivers | CDE-only | `kubectl get storageclass -o json` (parameters, mountOptions) | StorageClasses used by CDE enable encryption in transit where supported (EFS: `mountOptions: [tls]`; EBS CSI: node-to-volume encryption is inherent on Nitro instances) | Medium | 3.5.1.2 | Enable encryption in transit for storage drivers. For EFS, add `mountOptions: [tls]` to the StorageClass. EBS on Nitro instances provides encryption in transit by default. Supports PCI DSS Req 3.5.1.2. See: https://docs.aws.amazon.com/efs/latest/ug/encryption-in-transit.html |
| ST6 | Encrypted backups configured | CDE-only | `aws backup list-backup-vaults` + `aws backup describe-backup-vault` | AWS Backup vaults used for CDE data have encryption enabled (KMS). Mark N/A if no backup strategy is in place (flag as a separate concern) | Medium | 3.5.1.2 | Configure encrypted backups for CDE persistent data using AWS Backup with KMS encryption. Supports PCI DSS Req 3.5.1.2 for protecting stored cardholder data. See: https://docs.aws.amazon.com/aws-backup/latest/devguide/encryption.html |
| ST7 | EKS secrets envelope encryption with KMS | Cluster | `aws eks describe-cluster --name {cluster}` (encryptionConfig with `resources: ["secrets"]` and a KMS key ARN) | The cluster has envelope encryption enabled for Kubernetes secrets using a KMS customer-managed key (`encryptionConfig` present with `secrets` in resources) | High | 3.5.1.2 | Enable EKS envelope encryption of Kubernetes secrets with a KMS customer-managed key so that secret material stored in etcd is encrypted with a customer-controlled key. Supports PCI DSS Req 3.5.1.2 for protecting stored data with strong cryptography and associated key management. See: https://docs.aws.amazon.com/eks/latest/userguide/enable-kms.html |
