# Pillar: IAM Isolation (IAM1-IAM9)

Focus: Fine-grained IAM isolation ensuring least-privilege access for EKS workloads, MFA enforcement, and secure credential management. Grade each check PASS / FAIL / N/A with evidence, severity, and PCI DSS requirement mapping.

PCI DSS anchor: Requirement 7 (restrict access to system components), Requirement 7.2.5 (enforce least privilege), Requirement 7.3.3 (default deny-all), Requirement 8 (identify users and authenticate access).

Reference: [Building PCI DSS-Compliant Architectures on Amazon EKS — §6 Fine-grained IAM Isolation](https://aws.amazon.com/blogs/containers/building-pci-dss-compliant-architectures-on-amazon-eks/)

| Check ID | Check Name | CDE Scope | Data Source | What to Look For | Severity if Failed | PCI DSS Req | Recommendation |
|----------|------------|-----------|-------------|------------------|-------------------|-------------|----------------|
| IAM1 | IRSA or Pod Identity configured for CDE | CDE-only | `kubectl get serviceaccounts -n {cde} -o json` (annotations `eks.amazonaws.com/role-arn` or Pod Identity associations) | CDE service accounts use IAM Roles for Service Accounts (IRSA) or EKS Pod Identity — not relying on node-level instance profiles | Critical | 7.2.5 | Implement IRSA or EKS Pod Identity for all CDE workloads. This ensures each pod gets only the IAM permissions it needs, rather than inheriting the node's broad instance profile. Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html |
| IAM2 | No wildcard IAM actions in CDE roles | CDE-only | `aws iam get-role-policy` / `aws iam list-attached-role-policies` (for roles referenced by CDE service accounts) | IAM policies attached to CDE roles do not contain `Action: "*"` or overly broad action patterns | High | 7.2.5 | Scope IAM policy actions to specific, required operations (e.g., `s3:GetObject` not `s3:*`). Wildcard actions violate least privilege. Use IAM Access Analyzer to identify unused permissions. Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html |
| IAM3 | No wildcard IAM resources in CDE roles | CDE-only | `aws iam get-role-policy` / `aws iam list-attached-role-policies` | IAM policies attached to CDE roles do not contain `Resource: "*"` — resources are scoped to specific ARNs | High | 7.2.5 | Scope IAM policy resources to specific ARNs (e.g., a specific S3 bucket, DynamoDB table). Never use `Resource: "*"` unless the API does not support resource-level permissions. Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html |
| IAM4 | Dedicated IAM roles per CDE service account | CDE-only | `kubectl get serviceaccounts -n {cde} -o json` + IAM role inspection | Each CDE service account maps to a unique IAM role — no shared roles across different workloads | Medium | 7.2.5 | Create dedicated IAM roles per CDE workload/service account. Shared roles make it impossible to enforce least privilege per workload. Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html |
| IAM5 | MFA enforced for cluster admin access | Cluster | `aws iam list-mfa-devices --user-name {admin-users}` | IAM users with EKS cluster admin access have MFA enabled. Mark N/A if cluster access is exclusively via SSO/federated roles | High | 8 | Enable MFA for all IAM users with EKS cluster administrative access. Use AWS IAM Identity Center (SSO) with MFA-enforced policies for federated access. Supports PCI DSS Req 8 (authenticate access). See: https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_mfa.html |
| IAM6 | EKS access entries configured | Cluster | `aws eks list-access-entries --cluster-name {cluster}` | Cluster uses EKS access entries (API-based access management) rather than relying solely on aws-auth ConfigMap | Medium | 7.3.3 | Configure EKS access entries for API-managed cluster access. Access entries provide better auditability and support for conditions vs the legacy aws-auth ConfigMap. Supports PCI DSS Req 7.3.3 (default deny). See: https://docs.aws.amazon.com/eks/latest/userguide/access-entries.html |
| IAM7 | No overly permissive cluster access policies | Cluster | `aws eks list-associated-access-policies --cluster-name {cluster} --principal-arn {arn}` | No access entries use `AmazonEKSClusterAdminPolicy` for service accounts or automation principals — admin access is reserved for human operators | High | 7.2.5 | Restrict `AmazonEKSClusterAdminPolicy` to named human administrators only. Automation and service accounts should use scoped policies (e.g., `AmazonEKSViewPolicy`, namespace-scoped custom policies). Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/eks/latest/userguide/access-policies.html |
| IAM8 | No long-lived IAM access keys | Cluster | `aws iam list-access-keys --user-name {users-with-eks-access}` | No long-lived IAM access keys exist for users with EKS access; temporary credentials (STS) are used instead. Mark N/A if all access is via SSO/roles | High | 8 | Use AWS STS temporary credentials and IAM roles instead of long-lived access keys. Rotate or delete any existing access keys for EKS users. Supports PCI DSS Req 8 (secure authentication). See: https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html |
| IAM9 | IAM Access Analyzer findings resolved | Cluster | `aws accessanalyzer list-findings --analyzer-arn {arn} --filter "status={ACTIVE}"` | No active IAM Access Analyzer findings related to EKS roles or policies. Mark N/A if Access Analyzer is not enabled (flag as finding in LOG pillar) | Medium | 7.2.5 | Resolve all active IAM Access Analyzer findings for EKS-related roles. Use Access Analyzer to identify unused permissions and external access grants. Supports PCI DSS Req 7.2.5. See: https://docs.aws.amazon.com/IAM/latest/UserGuide/what-is-access-analyzer.html |
