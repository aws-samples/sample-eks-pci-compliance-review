# Pillar: Pod Security Controls (PS1-PS12)

Focus: Pod Security Standards (PSS) and container hardening to enforce secure configuration baselines on EKS workloads in PCI DSS environments. Grade each check PASS / FAIL / N/A with evidence, severity, and PCI DSS requirement mapping.

PCI DSS anchor: Requirement 2.2 (secure configuration hardening), Requirement 2.2.1 (single purpose/function), Requirement 2.2.3 (primary functions with different security levels on separate systems), Requirement 2.2.6 (system security parameters configured to prevent misuse), Requirement 10.4 (audit logs reviewed), Requirement 11.5.1 (intrusion detection), Requirement 11.5.2 (change detection).

Reference: [Building PCI DSS-Compliant Architectures on Amazon EKS — §2 Pod Security Controls](https://aws.amazon.com/blogs/containers/building-pci-dss-compliant-architectures-on-amazon-eks/)

| Check ID | Check Name | CDE Scope | Data Source | What to Look For | Severity if Failed | PCI DSS Req | Recommendation |

| PS1 | PSA enforce=restricted on CDE namespaces | CDE-only | `kubectl get namespace {cde} -o json` (labels `pod-security.kubernetes.io/enforce`) | CDE namespaces have PSA label `pod-security.kubernetes.io/enforce: restricted` | Critical | 2.2, 2.2.1 | Set Pod Security Admission to `enforce: restricted` on all CDE namespaces. This is the primary admission gate ensuring non-compliant pods cannot enter the PCI environment. Supports PCI DSS Req 2.2 for secure configuration hardening. See: https://kubernetes.io/docs/concepts/security/pod-security-admission/ |
| PS2 | PSA audit and warn modes configured | All | `kubectl get namespace -o json` (labels `pod-security.kubernetes.io/audit`, `pod-security.kubernetes.io/warn`) | Namespaces have PSA audit and warn labels configured for compliance reporting and developer feedback | Low | 10.4 | Configure PSA `audit` and `warn` modes alongside `enforce` to log violations to Kubernetes audit logs and provide developer feedback. Supports PCI DSS Req 10.4 for audit log review. See: https://kubernetes.io/docs/concepts/security/pod-security-admission/ |
| PS3 | runAsNonRoot enforced in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (securityContext.runAsNonRoot) | All pods in CDE namespaces have `runAsNonRoot: true` in their securityContext (pod or container level) | High | 2.2 | Set `securityContext.runAsNonRoot: true` on all CDE workloads. This creates a security boundary limiting the impact of container compromise. Supports PCI DSS Req 2.2 (SecurityContext best practices). See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| PS4 | readOnlyRootFilesystem in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (securityContext.readOnlyRootFilesystem) | All containers in CDE namespaces have `readOnlyRootFilesystem: true` | High | 2.2 | Set `securityContext.readOnlyRootFilesystem: true` on CDE containers. This prevents runtime modifications to the container image and blocks attackers from writing malicious files. Use emptyDir or tmpfs for writable paths. Supports PCI DSS Req 2.2. See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| PS5 | allowPrivilegeEscalation=false in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (securityContext.allowPrivilegeEscalation) | All containers in CDE namespaces have `allowPrivilegeEscalation: false` | High | 2.2 | Set `securityContext.allowPrivilegeEscalation: false` on all CDE containers. This blocks containers from gaining additional privileges through SUID binaries or kernel vulnerabilities. Supports PCI DSS Req 2.2. See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| PS6 | seccompProfile RuntimeDefault applied in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (securityContext.seccompProfile) | CDE pods have `seccompProfile.type: RuntimeDefault` (or stricter) | Medium | 2.2 | Apply `seccompProfile: { type: RuntimeDefault }` to CDE pods. This filters dangerous system calls that are not needed for normal application operation. Supports PCI DSS Req 2.2 (SecurityContext best practices). See: https://kubernetes.io/docs/tutorials/security/seccomp/ |
| PS7 | No privileged containers in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (securityContext.privileged) | No container in CDE namespaces has `privileged: true` | Critical | 2.2.3 | Remove the `privileged: true` setting from all CDE containers. Use specific Linux capabilities instead if elevated access is needed. Privileged containers have full host access and break all container isolation guarantees. Supports PCI DSS Req 2.2.3. See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| PS8 | hostPath volumes disabled in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (volumes[].hostPath) | No pod in CDE namespaces mounts hostPath volumes | Critical | 2.2.6 | Remove all hostPath volume mounts from CDE workloads. hostPath allows containers to access sensitive host filesystem directories, breaking container-to-host isolation. | PS9 | hostNetwork disabled in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (spec.hostNetwork) | No pod in CDE namespaces has `hostNetwork: true` | Critical | 2.2.6 | Disable `hostNetwork` on all CDE pods. hostNetwork shares the host's network namespace, bypassing network policy enforcement and breaking CDE network segmentation. | PS10 | hostPID disabled in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (spec.hostPID) | No pod in CDE namespaces has `hostPID: true` | High | 2.2.6 | Disable `hostPID` on all CDE pods. hostPID allows containers to access host processes, enabling lateral movement and privilege escalation. | PS11 | hostIPC disabled in CDE | CDE-only | `kubectl get pods -n {cde} -o json` (spec.hostIPC) | No pod in CDE namespaces has `hostIPC: true` | High | 2.2.6 | Disable `hostIPC` on all CDE pods. hostIPC allows containers to access host inter-process communication, potentially exposing shared memory. Supports PCI DSS Req 2.2.6. See: https://docs.aws.amazon.com/eks/latest/best-practices/security.html |
| PS12 | Runtime security monitoring deployed | Cluster | `kubectl get daemonsets -A` (Falco) + `aws guardduty get-detector` (EKS Runtime Monitoring) | Either Falco is deployed as a DaemonSet OR GuardDuty EKS Runtime Monitoring is enabled to detect runtime security violations | High | 10.4, 11.5.1 | Deploy Falco as a DaemonSet for runtime behavioral detection OR enable GuardDuty EKS Runtime Monitoring.
